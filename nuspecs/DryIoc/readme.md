## Hello Sailor,

### Compile-time Dependency Injection

DryIoc has an *optional* compile-time Dependency Injection
(previously it was available as a separate DryIocZero package).

You may ignore this information if you don't want to use the compile-time DI — everything works at runtime without it.
But compile-time DI gives you faster startup, smaller memory footprint, and AOT/trimming compatibility!


### Automated Setup (on NuGet install / restore)

When you add the `DryIoc.dll` NuGet package reference and run `dotnet build` (or `dotnet restore`),
the following happens **automatically**:

1. A `CompileTimeDI\` folder is created in your project with:
   - `Container.Generated.tt` — the T4 template that generates the compile-time container  *(always updated from the package)*
   - `CompileTimeRegistrations.Example.cs` — example service types for reference  *(always updated from the package)*
   - `CompileTimeRegistrations.ttinclude` — **your** registration file  *(copied only on first install — safe to customize)*
   - `Container.Generated.cs` — the generated compile-time container  *(copied only on first install — regenerated by T4 on build)*
2. A `.config\dotnet-tools.json` is created with the [dotnet-t4](https://www.nuget.org/packages/dotnet-t4/) tool  *(copied only on first install — safe to add your own tools)*
3. The `dotnet-t4` tool is restored automatically.

After the first successful build, subsequent Debug builds will **automatically regenerate** `Container.Generated.cs`
from your registrations in `CompileTimeRegistrations.ttinclude`.


### How to configure compile-time DI

1. Open `CompileTimeDI\CompileTimeRegistrations.ttinclude` in your project.
2. Edit `GetContainerWithRegistrations()` to register your services (using the same DryIoc API you already know).
3. Specify resolution roots in `SpecifyResolutionRoots` or `CustomResolutionRoots`.
4. Build the project in **Debug** mode. After the first successful build, T4 generation runs automatically on the next build.
5. Check `CompileTimeDI\Container.Generated.cs` for the generated container and any warnings.
6. Use the generated container in your app:

```csharp
// Compile-time container is primary (fast); runtime registrations are the fallback
// for services not in the compile-time container (e.g. open-scope or runtime-only services)
var container = new Container(rules => rules
    .WithCompileTimeContainer(CompileTimeContainer.Instance));

// Optionally register additional runtime-only services
// (services not generated by T4, e.g. those requiring runtime state)
container.Register<SomeRuntimeService>();
```


### Updating to a new DryIoc.dll version

After updating the package version:

- `Container.Generated.tt` and `CompileTimeRegistrations.Example.cs` are automatically refreshed.
- **Your** `CompileTimeRegistrations.ttinclude` and `Container.Generated.cs` are **never overwritten** — your customizations are preserved.
- Build in Debug mode to regenerate `Container.Generated.cs` with the updated template.


### Opting out of automatic generation

Set `<SkipCompTimeGen>true</SkipCompTimeGen>` in your project file to disable automatic T4 generation while keeping the copied files.


### T4 Text Template Transformation Tooling

The `dotnet-t4` CLI tool is automatically set up as a local tool in `.config\dotnet-tools.json`.

For editing T4 template files you may use:
- [T4 Support extension](https://marketplace.visualstudio.com/items?itemName=zbecknell.t4-support) in VS Code
- [ForTea plugin](https://plugins.jetbrains.com/plugin/11634-fortea) for JetBrains ReSharper in Visual Studio
- The native T4 support in JetBrains Rider
