## Hello Sailor,

### Compile-time Dependency Injection (optional)

Compile-time DI gives faster startup, smaller footprint and AOT/trimming compatibility.
Skip this section if you only need runtime DI — everything works without it.

**On first `dotnet build`** the package scaffolds your project:

| File | When copied |
|------|-------------|
| `CompileTimeDI\Container.Generated.tt` | every build (refreshed from package) |
| `CompileTimeDI\CompileTimeExampleServices.cs` | every build (refreshed from package) |
| `CompileTimeDI\CompileTimeRegistrations.ttinclude` | first install only — safe to customize |
| `CompileTimeDI\Container.Generated.cs` | first install only — regenerated by T4 on next build |
| `.config\dotnet-tools.json` | first install only — [dotnet-t4](https://www.nuget.org/packages/dotnet-t4/) tool |

### Usage

1. Edit `CompileTimeDI\CompileTimeRegistrations.ttinclude` — add your services to `GetContainerWithRegistrations()` and set resolution roots.
2. Build in **Debug** mode. The second build regenerates `Container.Generated.cs` via T4.
3. Check `Container.Generated.cs` for the generated container and any warnings.
4. Use the compile-time container (runtime registrations on the same container are the fallback):

```csharp
var container = new Container(rules => rules
    .WithCompileTimeContainer(CompileTimeContainer.Instance));
```

### Updating the package

`Container.Generated.tt` and `CompileTimeExampleServices.cs` are always refreshed.
`CompileTimeRegistrations.ttinclude`, `Container.Generated.cs`, and `.config\dotnet-tools.json` are **never overwritten**.

### Opting out

Add `<SkipCompTimeGen>true</SkipCompTimeGen>` to your project file to disable T4 regeneration.
